# 0001. Проверка снаружи без второго сервера

Статус: **предложено, не реализовано.** Открытый вопрос этапа 0.

## Проблема

Установщик объявляет панель опубликованной только после проверки снаружи. Сейчас
единственный способ — RemoteProbe (`cmd/auditdsec-probe`) на отдельной машине владельца.
Для новичка с одним VPS это непреодолимо: второго сервера нет, и установка заканчивается
`external_check_unavailable` или флагом `--no-external-check`, после которого панель
честно не считается опубликованной.

Ограничения, которые решение обязано соблюдать:

- проверка с самого VPS (`curl` на свой адрес) ничего не доказывает и не засчитывается;
- отсутствие проверки никогда не выдаётся за подтверждённую публикацию;
- никакие секреты не уходят стороннему «проверяльщику портов»;
- не придумывается URL публичного сервиса, которого не существует;
- первый вход `admin` / `admin` без кода сохраняется.

## Решение: проверяльщик — устройство самого владельца

Внешний узел у новичка уже есть: телефон или ноутбук, с которого он откроет панель.
Добавляется второй тип провайдера внешней проверки — **визит владельца**:

1. На этапе выбора порта установщик поднимает временный слушатель с одноразовым nonce
   (он уже есть: `auditdsec probe-listen`) и печатает ссылку вида
   `http://203.0.113.10:27431/.well-known/auditdsec-probe/3f9a…` и QR-код в терминале.
2. Просьба: «Откройте ссылку на телефоне **через мобильный интернет** (Wi-Fi выключить)».
   Страница отвечает «Порт доступен снаружи, вернитесь в терминал».
3. Слушатель засчитывает визит, только если запрос пришёл **с адреса вне сервера**: не
   loopback, не private/CGNAT/link-local, не один из адресов самого VPS и не его
   исходящий адрес. Визит из той же сети за NAT (hairpin) так не пройдёт — поэтому
   мобильный интернет.
4. Тайм-аут ожидания (например, 5 минут) → `external_check_unavailable` с подсказкой; это
   не «порт закрыт». Пользователь может нажать Enter, чтобы пропустить, — тогда итог
   «NOT published (outside check skipped)», как сейчас с `--no-external-check`.
5. Тот же визит повторяется для порта 80, если нужен HTTP-01 (для IP — всегда).
6. Финальная проверка после запуска: установщик печатает итоговую ссылку и ждёт, пока
   владелец откроет её **с того же внешнего устройства**; агент фиксирует запрос к
   `/api/v1/setup/state` с внешнего адреса по HTTPS. Доверенность сертификата при этом
   проверяет сам установщик по системному хранилищу CA (соединение к собственному
   адресу или к loopback с тем же SNI): браузер владельца тут не свидетель — человек
   мог нажать «всё равно продолжить».

Что это доказывает: входящие соединения на выбранный адрес и порт доходят до VPS из
реального интернета (сеть оператора связи владельца). Что не доказывает: доступность из
любой точки мира (гео-фильтры провайдера) — так и пишется в итоге:
`Outside: reached from 198.51.100.23 (your device), not from an independent probe`.

Неинтерактивная установка (`--yes`) по-прежнему требует RemoteProbe или явного
`--no-external-check`.

## Почему не другое

| Вариант | Почему нет |
|---|---|
| Публичный RemoteProbe проекта | нужен постоянно работающий сервис с бюджетом и защитой от злоупотреблений; пока его нет, ссылаться на него нельзя. Контракт RemoteProbe уже позволяет подключить такой сервис позже одной настройкой `--probe-url` |
| Сторонние «проверялки портов» | не аутентифицированы, меняют API, их ответ нельзя связать с нашим nonce; часть из них — сканеры |
| Проверка через Let's Encrypt (успешный выпуск = порт 80 открыт) | доказывает только 80/443 и только для ACME, не для выбранного порта панели; к тому же тратит лимиты production |
| SSH-туннель обратно с ноутбука | требует от новичка того же уровня, что и второй сервер |

## Объём работ (когда возьмёмся)

- `probe-listen`: режим ожидания визита с проверкой адреса источника и выводом QR
  (QR — без внешних библиотек, кодировщик в несколько сотен строк или текстовая ссылка).
- Установщик: выбор провайдера (`RemoteProbe` / `визит владельца` / пропуск), отдельные
  формулировки результата, тот же набор кодов ошибок.
- Агент: отметка внешнего визита к `/api/v1/setup/state` в журнале (адрес, время), без
  секретов.
- Стенд: «внешнее устройство» — контейнер в отдельной сети с `curl`.
